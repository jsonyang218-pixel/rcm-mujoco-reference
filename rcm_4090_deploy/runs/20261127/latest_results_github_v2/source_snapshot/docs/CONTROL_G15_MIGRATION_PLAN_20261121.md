## 1. 目标与关键结论

将根目录 `simulation_driver/ros_msg/src/robot_control/kinematics.py` 的 G15 换算接入当前部署项目，保留可复现的 G10 对照；随后单独验证控制器的连续目标累积，解决小动作逐帧取整后丢失的问题。

假设：连续目标累积可能降低小动作无响应比例、改善末端跟踪。G15 本身是否改善终值必须配对验证，因为其每个手柄计数比 G10 大 50%。目标累积不能创造协议不支持的分数手柄目标，也不能据此保证 0.35 µm 的停稳精度。

默认起点保持针尖超过 RCM 约 **4 mm**，不把起点改成 23–24 mm，也不把针尖到 RCM 的距离锁死为 4 mm。当前配置明确记录：

```text
config.json → encoder_reference
robot_counts_ABC = [0, 1466018, 893518]
needle_tip_distance_at_reference_mm = 4.0
physical_needle_reference_confirmed = false
```

`rcm/reference.py:state_from_task()` 使用 `length_mm = tip_reference_mm + C_insertion_m * 1000`。因此 C=0 时约 4 mm，C 推进约 19–20 mm 后，针尖距 RCM 才约 23–24 mm。4 mm 是当前模型零位设定；配置尚未将其标记为实物针具标定完成。

在针轴倾角 θ≈76.236°、忽略最后一次机器人编码器取整时：

| 换算版本 | A 每手柄 count | B 每手柄 count | C 每手柄 count | 距 RCM 4 mm 时 A/B 对应针尖弦长 |
|---|---:|---:|---:|---:|
| 当前 G10 | 0.015° | 0.0075° | 1.175130 µm | 约 1.017 / 0.524 µm |
| 待接入 G15 | 0.0225° | 0.01125° | 1.762695 µm | 约 1.526 / 0.785 µm |

A 绕模型 Y 轴改变方位，B 改变针轴倾角，C 沿针轴进退。实际 A/B 针尖位移还随当前距离和姿态变化。将任意 XYZ 修正换成 ABC，需要运动学联动；上述单轴数字不能当作固定 XYZ 步距。

## 3. 实现顺序与文件职责

### P1：显式选择驱动，先实现忠实 G15 路径

- `mujoco_model/driver_loader.py`：增加显式版本选择，默认仍为 G10；G15 使用独立命名空间加载，启动时校验路径、哈希和 `CONTROL_GEAR`。保留原 G15 文件；如需部署快照，新增独立版本目录和清单，不覆盖 G10。
- `mujoco_model/motor_backend.py`：接收选定的运动学模块；`DriverModel` 和 `MotorExecution` 使用同一版本上下文。两个版本不能依赖 `sys.path` 先后顺序隐式切换，也不能复用错误的 `sys.modules['robot_control.kinematics']` 缓存。
- `rcm/motor_execution.py`：透传版本，记录驱动身份；保持现有电机响应与协议语义。G15 忠实路径继续采用源码已有的机器人编码器取整和手柄取整。

消息 `handleEncoderA/B/C/E` 始终是 int32 **累计绝对目标**。会话保存机器人与手柄锚点，相对于锚点解码；重复同一消息必须幂等。不能在接收端收到一次就再次累加，也不能用方向标志关闭来代替停止命令。

### P2：在策略控制器增加连续目标累积

当前 `lerobot_training/eval_policy.py` 每拍执行 `trial_state = actual_state + scale * action`。若每拍动作均小于量化阈值，目标反复回到反馈附近，小动作可能持续丢失。

拟新增 `rcm/control_target.py`，负责持续保存 ABC 意图目标，并在评估器接入：

```text
reset: q_intent = 实际 ABC 状态
每拍: q_trial = q_intent + scale × clipped_policy_delta
      施加已有任务限位及相对实际状态的前馈距离上限
      由 q_trial 计算机器人编码器目标，再计算累计整数手柄目标
      从整数手柄反算真正可执行的机器人目标，完成全部验证
      验证成功后提交 q_intent 和命令；然后推进一个控制周期
```

意图目标采用明确单位的浮点 ABC（deg、deg、mm），保留分数步信息；协议发送时仍使用整数。量化残差定义为“意图目标减去协议可重现目标”，用于诊断，不再另行积分同一份动作。

累计目标相对反馈的最大领先量使用现有速度上限乘控制周期：A/B 各 0.5°、C 0.1 mm，不新增可调增益。饱和后将意图目标提交为受限值，防止继续积累超限动作。保留当前缩放尝试序列 `1, 0.5, 0.25, 0.125, 0.0625, 0`；零缩放表示不加入新动作，可能仍有先前已接受目标待电机跟踪。

缩放尝试、限位和 B 分支校验采用“只读预演 → 一次提交”。拒绝候选不得推进时间或修改电机、锚点、意图目标、动作历史。当前 `advance_robot()` 在 `consume()` 后还有校验，需要把可能拒绝命令的检查前移；执行中故障则进入明确故障停止流程，不在已推进的状态上试下一档动作。

重置、换目标、会话重连、watchdog 故障、明确停止时清理意图与残差并按当前反馈重新锚定。达到几何阈值后保持最后一个已接受目标，继续正常执行直到真正停稳；不得通过覆盖实际状态或 `hold()` 伪造成功。

`previous_action` 保持“本拍接受的 ABC 命令增量”语义，记录限幅、缩放和领先量限制后的实际接受值；不能悄悄换成编码器位移或手柄差值。输入分布变化需在结果中单独报告，现有权重不自动视为兼容验证通过。

### P3：按控制输入类型接入，避免重复累积

策略输出为 `[dA_deg, dB_deg, dC_mm]`，走 ABC 目标链路，不能作为 XYZ 传给 `cartesian_handle_delta_float()`。

只有本来输出笛卡尔误差的控制器才接入该接口；输入应转换到驱动模型坐标系、单位 mm，并明确传入交接点反馈和针具偏置。该接口内部已经取整机器人编码器，返回的浮点手柄不是完全连续逆解，返回的理想机器人目标也不等于最终整数手柄可重现目标。

`rcm/visual_servo.py` 和既有几何教师已经保存连续命令目标。接入公共适配器时复用其已有意图目标，不再额外累积一次；几何教师的累积版使用同一抗饱和规则。

### P4：版本化日志、评估入口和回退

增加明确的 `driver_variant`、`controller_variant` 与新执行契约版本，保留旧版评估解析。`scripts/research/overnight_cfix_eval.py` 当前没有完整的迁移矩阵和 screen10 入口，需先扩展或新增专用评估模块，再生成 SOP 卡；本文不提供尚不存在的可执行 CLI。

每拍同时记录原始策略动作、接受增量、实际 ABC、意图目标、累计手柄目标、量化后机器人目标、量化残差、针尖距 RCM、实际针尖运动、限幅原因与停稳状态。每次运行保存代码/场景/驱动/配置/权重哈希。

第一版通过显式配置启用，默认保持 G10。验收后再提出默认切换变更；任何回退均使用原 G10 配置，不覆盖原文件。

## 5. 实验卡：阶段、门禁和预算

所有完整闭环保持 `seed=42+episode_index`、每目标最多 1600 步、50 ms 周期。严格成功为针尖误差 ≤0.35 µm 且连续 3 帧实际编码器停稳；停稳要求编码器到达量化目标并且实际速度为零。另报终值均值、中位数、最大值、严格成功数、无响应比例、限位次数及推理延迟。

默认从 C=0、针尖超过 RCM 约 4 mm 的零位启动。smoke 也从该起点走链路；另用静态运动学核对 0.5 mm、4 mm 和冻结目标附近姿态的单计数位移，这些探针不作为完整任务成功率。

|---|---|---|
| S0 资产预检及确定性检查 | 四变体；10 分钟 | 版本、单位、配置、权重及输出路径明确；所有协议检查通过才进入 S1 |
